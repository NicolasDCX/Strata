# Development guide

Build and run instructions are in the [README](../README.md). This file covers working on the code.

## Presets

| Preset | Contents | Use |
|---|---|---|
| `release` | everything, `-O3` | normal use, benchmarks |
| `relwithdebinfo` | everything, optimised with symbols | profiling |
| `debug` | everything, no optimisation | debugging |
| `headless` | Core, Geometry, Sculpt, Application, tests, benchmark | CI machines without Qt or a GPU |

Build trees go to `build/<preset>/`. Executables are in `build/<preset>/bin/`.

CMake options: `SE_BUILD_APP`, `SE_BUILD_TESTS`, `SE_BUILD_BENCH` (all `ON` by default).

## Dependencies

CMake looks for an installed copy first and downloads a pinned version otherwise (`FetchContent`):

| Dependency | Used by | Lookup |
|---|---|---|
| GLM | all modules | `find_package(glm)` |
| Vulkan headers | Renderer | `VULKAN_SDK`, else Vulkan-Headers |
| glslang | shader build step | `glslangValidator` / `glslang` on `PATH` or in `VULKAN_SDK`, else built from source |
| GoogleTest | tests | `find_package(GTest)` |
| Qt 6 | Renderer, Editor | `CMAKE_PREFIX_PATH` |

The application never links the Vulkan loader: `QVulkanInstance` loads it at runtime and exposes the entry points through `QVulkanFunctions` / `QVulkanDeviceFunctions`.

## Shaders

GLSL sources are in `src/Renderer/Shaders/`. At build time each is compiled to SPIR-V and converted to a C++ header (`cmake/EmbedSpirv.cmake`) under `build/<preset>/generated/`, so the executable needs no shader files at runtime.

The push constant block `FrameConstants` must match `render::MeshFrameConstants` in `MeshPipeline.h`, in `mesh_paged.vert` (the vertex-pulling shader, the only vertex shader) and `mesh.frag`. `mesh_paged.vert` also hard-codes the vertex pool slot layout written by `ResidentMeshBuffers::prepare`: per slot, page-size positions then page-size normals, three floats each.

## Conventions

- Namespaces follow modules: `se::core`, `se::geo`, `se::sculpt`, `se::app`, `se::render`, `se::editor`.
- Includes are written from `src/`, for example `#include "Geometry/Mesh.h"`.
- Types `PascalCase`, functions and variables `camelCase`, members `m_camelCase`, constants `kPascalCase`.
- Recoverable failures return `core::Result<T>` (`std::expected`). Broken invariants use `SE_ASSERT`. No exceptions are thrown by project code.
- Vulkan objects are owned by move-only RAII types. Raw handles are passed around only as non-owning parameters.
- Code that runs per vertex must not allocate, lock or make virtual calls.
- Geometry is referred to by id (`VertexId`, `TriangleId`), never by pointer or by position in a container. Do not renumber or move elements after creation.
- In hot loops, take `mesh.positions()` / `mesh.triangles()` into local views once; do not call them per element.
- Mesh vertex data and the BVH are written only by the sculpt thread and read by others only under `AppController::documentMutex()`. Code inside `core::parallelFor` writes only the elements of its own chunk.
- A change to a brush or to the stroke pipeline must keep `ParallelReference.*` passing: threaded and single-threaded results are required to be bit-identical.
- Project code must compile without warnings under `-Wall -Wextra -Wpedantic -Wshadow -Wconversion`.
- Do not name anything `slots`, `signals` or `emit`, even in headers without Qt: Qt defines them as macros and the header may be included after Qt.
- Renderer code that decides what to draw or upload (`Frustum`, `ChunkPageMap` with `mergeIndexRuns`, `PagePool` with `markDirtyVertexPages`) is kept free of Vulkan so that it can be unit tested headless; put new bookkeeping there, not in the `Vulkan/` classes.

Run one test: `build\release\bin\se_sculpt_tests.exe --gtest_filter=BrushTest.*`

`SculptEngine --selftest <dir>` drives the real window (see `Editor/SelfTest.cpp`). Use it after any change to the renderer or the editor; look at the PNG files it writes, not only at the exit code.

With `--selftest-reference <dir>` the standard self-test compares its 10 scripted captures (01 to 11) with an earlier run, and with the default pools every capture checks full coverage (all visible chunks drawn, no stale page). Make a reference run before a renderer change and compare after it. If the real mouse is over the window while the test runs, its events reach the viewport and cause extra strokes; keep the mouse away.

After a change to culling or normal cones, run the standard self-test twice, first with `--normal-cones off` and then with the default settings and `--selftest-reference <first dir>`. The scripted captures (01 to 11 and the strong-deformation captures 17_) must be identical, and so must every within-run culling comparison (off, frustum, on, unmerged, in 16 views). The report also gives sculpt-thread cost per dab (`BVH refit + normal cones`) for both runs.

After a change to culling or residency, also run the pressure scenario three times: default pools as the reference, then with `--gpu-budget-fraction 0.9` and `0.25`, each with `--selftest-reference <reference dir>` (commands in the README). At 0.9 the zoomed captures must match the reference exactly; at 0.25 the report must show the nearest chunks drawn, 0 stale pages after the stroke, and undo/redo restoring the picture. The live stroke's dab count depends on timing, so p04/p06/p07 are compared only within a run; it is undone before the scripted strong deformations (p08_), which are compared with the reference wherever every visible chunk is drawn. Known exception: at 0.9, 1 to 5 pixels of the p08 captures after redo differ from the reference with or without normal cones (README, Known limitations). Compare each budgeted run with cones against the same budget with `--normal-cones off` before attributing a difference to culling.

After a change to stroke input handling or Move, run `--selftest-scenario move` at `--subdivisions 11` with `--move-updates all` and `latest`: three live Move strokes at 500 inputs per second, then undo all and redo all. It must PASS, and the three mesh hashes it notes must be equal in both modes. Keep the mouse away: real pointer events become extra inputs.

To measure input-to-frame latency, run `--selftest-scenario latency` (README, "Input to frame in the Vulkan viewport at 84M"). It traces one Draw and one Smooth stroke at radius 0.25 with 120 Hz scripted input, and writes per-input rows (enqueue, start, done, dab commit sequence and time, matched frame), per-frame rows (start, consume time and commit sequence, submit, stale pages, held-back uploads), change notifications and `UpdateRequest` times to `trace_<brush>.csv`. The report notes p50/p95 per stage and the stroke's stage timers. The scripted input shares the GUI timer, so it reaches the viewport on Windows' 15.6 ms timer grid. Measure from enqueue, as the report does. Keep the mouse away.

After a change to undo/redo or the document lock, run `--selftest-scenario history` at `--subdivisions 10`, with `--threads 0` and the default, and with `--history-normals before` and `under`. It repeats undo all + redo all of typical and strong strokes while frames render back to back. It must PASS (exact end state, cones, the undone mesh pixel-identical to the initial one), and its report gives the renderer's lock wait per frame, the commands' hold and total, and the scratch. Run it alone: stray input to the full-screen window changes the strokes.

## Adding a brush

1. Create `src/Sculpt/Brushes/MyBrush.h/.cpp` deriving from `sculpt::Brush`. Implement `name()`, `mode()` and `apply()`. Only write `ctx.positions[v]` for `v` in `ctx.vertices`.
2. Add the files to `src/Sculpt/CMakeLists.txt`.
3. Register it: built-in brushes are added in `BrushLibrary::BrushLibrary()` with a `BrushId` enumerator; brushes defined elsewhere call `BrushLibrary::add()` at runtime.
4. Give it a toolbar entry in `MainWindow::buildToolbar()`.
5. Add tests next to the existing ones in `tests/SculptTests/BrushTests.cpp`.

Normals, BVH, undo and GPU upload are handled by `StrokeProcessor` for every brush. To use helper threads, wrap the per-vertex loop in `core::parallelFor(ctx.jobs, count, kBrushParallelGrain, ...)` and take working memory from `ctx.scratch`.

## Debugging and profiling

- `--validation` enables the Khronos validation layer if the Vulkan SDK is installed. Messages go to stderr through Qt's `qt.vulkan` logging category.
- RenderDoc can capture the application directly; there is a single render pass per frame.
- The status bar shows the duration of the last input sample, the worst sample of the stroke, the last GPU upload and the CPU time of the last frame.
- `se_bench adjacency <level> <helpers> [wide] [derived] [pgather]` runs fixed Draw, Smooth and Move strokes on the stroke processor alone and prints per-stage times per dab (gather split into query, select, undo record and average normal; commit split into publish, local refits and cones, top level), the edit scratch and a hash of all positions and normals. `pgather` selects the parallel gather and `pmark` the parallel BVH leaf marking (the bench's defaults are serial, so both can be compared); the hashes must not change.
- `se_bench live <level> [helpers] [rounds] [pgather] [pmark]` sends strokes through `AppController` with inputs every 2 ms and a reader thread taking the document lock every 4 ms, and prints p50/p95/max of the lock hold per dab, reader wait, dab latency, input latency, the input backlog (max and at release) and the scratch.
- `se_bench rates <level> <helpers> [speed=S] [frame=F] [only=move] [mall|mlatest]` uses the editor's defaults and makes 2 s Draw, Smooth and Move strokes at radii 0.0625, 0.125 and 0.25 and input rates of 60, 120 and 240 Hz (Draw and Smooth at S units per second, default 1.5; a reader locks the document every F ms, default 16.67). It prints one `RATE` line per stroke: dabs, dabs per input, dabs per second, queue max and at release, drain after release, and p50/p95/max of queue wait, processing (all inputs, inputs without and with dabs), input to visible, dab latency and reader wait. It reads the controller's per-input samples (`InteractionStats::inputSamples`: queued, started and finished time and dabs of every stroke input). Each line also gives applied and coalesced (dropped) inputs, input to visible for every input (a dropped one is charged until the frame showing the input that replaced it), final release to visible, and a hash of the final mesh, which must not change between `mall` (every Move update applied) and the default latest-wins mode. `only=move` runs the Move strokes alone; `mlatest` turns latest-wins on in the modes that default to the old behaviour (`live`, `history`).
- `se_bench history <level> [helpers] [cycles] [pgather] [pmark] [hstage]` makes 3 typical and 5 strong strokes through `AppController`, then runs cycles of undo all + redo all while a reader locks the document every 4 ms. It prints p50/p95/max of the undo and redo lock hold, the total, the time before the lock and each stage inside the hold (positions, normals, dirty pages, refit + cones, top level; refit + cones also split into the chunks' box refits and normal cones as CPU time summed over the threads, the box refit into leaves, inner nodes and parent queueing, with the slowest and mean chunk and the node counts), the reader wait, the scratch and a hash after the cycles. `hstage` computes the normals before the lock; the hash must not change. In every `se_bench` mode, `dense` turns on the dense box refit (the bench's default is the incremental one, so both can be compared; the editor's default is dense). Likewise `icones` turns on incremental normal cones (the editor's default), `cfb=N` sets their fallback percentage (100: never recompute exactly), `closs` measures the extra triangles the widened cones let through from 14 fixed eyes (separate runs: it costs time), and `r=R` sets the dab radius of the `adjacency` and `live` strokes (default 0.25). `oreg` overlaps the region walk and leaf marking with the dab preparation (`nooreg` forces it off; the editor's default is off; `adjacency` then counts the overlapped regions and the region time moves from normals into the prepare wall time). `rates` also takes `only=draw`, `only=smooth`, `hz=R`, `rad=R` (one rate, one radius), `reps=N` (each stroke N times) and `dump=DIR` (each stroke's input samples and reader ticks as CSV); its RATE lines carry `seq=` (hashes are comparable between runs only at the same seq, because the BVH's background re-partitioning changes the gather order from stroke to stroke) and a `commit` latency (input queued to its last dab committed, free of the 8.33 ms steps that `visible` takes with 120 Hz input and a 60 Hz reader). `se_bench repeat <level> <helpers> <draw|smooth|move> [radius] [reps] [refresh] [fresh]` replays the rates stroke without timing and reports, per repeat, the dabs, dab centres, undo record order, positions and normals against the first, and the state and BVH triangle order after undo against startup (`fresh`: each repeat in a new controller). `strilinear` makes Smooth blend its kernel cells trilinearly, as before the band fix (the editor's default is the quadratic B-spline; `smoothdump <level> <dir> [updates] [radius] [strength] [passes] [quadratic|trilinear]` writes the positions, normals and dab centres of fixed Smooth strokes around the stroke for offline analysis). `sbinser` makes Smooth bin its kernel grid serially (the editor's default is parallel; `adjacency` prints Smooth's stages per dab, how many dabs binned in parallel, and the brush scratch). `pprep` overlaps each large dab's undo record, average normal and page staging (the editor's default; `adjacency` prints their wall time and how many dabs overlapped). `pregion` walks edit regions on the helper threads (the editor's default; `adjacency` then prints how many dabs walked in parallel and the stamp memory, `history` the region time before the lock and how many steps walked in parallel). `creuse` makes exact cones reuse the first pass's face normals (the editor's default); the history mode then prints both passes' CPU time, the second-pass triangles per step and the scratch, and `adjacency` prints them per edit. The history and live modes also print the cones exact / widened / turned off per step and the background rebuild's steps, chunks, compute time and publish hold.
- `se_bench [first] [last] [threads] [sweep]` isolates the geometry and sculpt costs from rendering. It prints a per-stage breakdown of an edit (gather, brush, normals, BVH), compares one thread with the job system, reports memory and construction time, measures lock waits through `AppController`, and with `sweep` compares page and chunk sizes. Run one size per invocation when comparing numbers: results at 5.2M triangles vary by 10% or more between runs.
- `SculptEngine --selftest <dir>` includes a live stroke with normal rendering and writes frame interval, frame CPU, frame GPU, lock wait and upload distributions to `report.txt`, plus culling measurements (chunks, triangles, draw calls, GPU and CPU time) for a full, a zoomed and a limb-only view.
- The status bar shows chunks drawn / total, triangles, draw calls and GPU time per frame, the GPU memory and the resident pages. `C` toggles culling while the application runs.
- GPU timings of a single pass are dominated by clock state: the GPU stays at power-saving clocks under light load (check with `nvidia-smi --query-gpu=clocks.gr --format=csv -l 1`). Compare the self-test's loaded rows ("64 passes per frame", GPU time per pass), or triangles submitted. A repeat count that leaves the frame well under the display interval does not load the GPU enough: 8 passes gave results that varied 2x between runs.
- Tests that use `AppController` must call `waitUntilIdle()` before reading results; edits are asynchronous.
- Log output goes to stderr. The application is a GUI-subsystem executable on Windows, so start it from a terminal with stderr redirected to see it: `SculptEngine.exe 2> log.txt`.

## Recommended next milestone

Done so far: latest-wins Move updates (README, "Latest-wins Move updates": 84M radius-0.25 Move drains in 14–26 ms instead of 1.3–5.0 s at 120–240 Hz, results bit-identical); incremental BVH and page-based uploads; the multithreaded sculpt engine; the paged, chunked geometry architecture (phase 4); per-chunk frustum culling with an optional GPU memory budget (phase 5); a single GPU storage path (page pools, sized for the whole mesh by default); and back-facing chunk culling with normal cones kept current by the sculpt thread's BVH refit, widened incrementally and rebuilt exactly in the background.

**Next:**

1. Large-footprint dab geometry for Draw and Smooth at 84M (visible p95 34–46 ms at radius 0.25): normals (edit region 4.55 + compute 2.99 ms per Draw dab), then the gather's vertex selection, then the Smooth brush. Details below.
2. Gather of large dabs: with the undo record, average normal and page staging overlapped (README, "Gather profile at 84M and overlapped dab preparation"), an 84M Draw dab with 11 helpers spends 2.0 ms in the chunk query and 3.3 ms in the vertex selection (first corners 1.0, distance test and falloff 1.75, join 0.6), both already parallel. Each overlapped step also takes longer than alone (record 1.35 → 1.5, normal 1.7 → 2.0 ms). For Smooth, the brush's kernel grid is now binned in parallel (README, "Smooth profile at 84M and parallel kernel-grid binning"): the brush is 6.1–7.0 ms at 84M, of which the kernel pass is 3.05 (already parallel), binning 1.7–2.1 and the Laplacian pass 1.2. The quadratic kernel blend that removes the Smooth bands (README, "Smooth bands: kernel-cell creases") reads 27 cells instead of 8 and adds about 1.9 ms per 84M dab to the kernel pass; normalising each cell's normal once per dab would take a division out of every tap.
4. Undo hold normals, a separate experiment: the parallel edit region (README, "Parallel edit region") took the region walk from 15.8 to 6.6 ms per 84M Draw dab and from 61 to 25 ms before each 84M undo, but the lock hold is unchanged. Its normals (12.7 of 28.6 ms at 84M): store final normals in the history entry, or compute each face normal once. README, "Normal recomputation at 84M".
5. Coarse fallback for chunks that do not fit a budget (`--lod`, opt-in): border-locked per-chunk simplification, crack-free, about 5.7% of a full copy, allocated only under a budget, one multi-draw-indirect call per pass. Next: re-simplify edited chunk groups in the background, so that groups of 4 chunks (about half the memory, `--lod-group-chunks 4 --lod-ratio 0.03125`) follow strong deformation; then they can become the default. Evaluation notes are in the fallback's report.
6. Find the cause of the 1 to 5 pixels that differ after heavy eviction under a 90% budget (README, Known limitations).
7. If the renderer's CPU time matters: avoid requesting every visible chunk's pages and rewriting the page table each frame when nothing changed (about 0.05 ms at 5.2M today).
8. Memory: compact adjacency is the default (-58 MiB at 5.2M) since the shared edit region removed its Move cost (README). Neighbour lists derived from the incident triangles exist as an opt-in (`--neighbors derived`, -40 MiB at 5.2M, construction -39%), but Smooth is 3 to 6% slower per edit: a derived ring costs about 44 ns against 7 ns for a stored row, mostly the triangle reads. Making it the default would need Smooth's Laplacian to stop reading neighbour rings, for example by accumulating over incident triangles (a different summation order, so not bit-identical with today's results). The largest serial part of a Move edit is now the BVH leaf queueing (0.42 of 1.47 ms at 5.2M), independent of the adjacency layout. Local BVHs built only for chunks that are queried.
9. Parallel mesh construction and spatial ordering (now the dominant startup cost), and parallel vertex selection in the brush path.
10. Tooling: a ThreadSanitizer build (Linux/Clang), the Vulkan validation layer, and CI on Linux and MSVC.

SSD streaming and multiresolution remain out of scope until the above is done.
Target: an edit under 2 ms at 5 to 10 million triangles for a normal-sized brush, and no visible stroke lag.
